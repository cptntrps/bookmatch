# bookmatch — a Goodreads taste-profile and recommendation service

## What it is

bookmatch is a Python service that builds a book-recommendation index from the UCSD Goodreads corpus and serves a taste-profile and recommendation app. It runs on the host `aurora` as the systemd unit `bookmatch.service`, executing this checkout in place. The service listens on port `:8092` and exposes an `/api/health` endpoint.

The repository contains the application package (`bookmatch/`), a one-time index builder (`scripts/build_index.py`), a dataset downloader (`scripts/download_dataset.sh`), a deploy script (`deploy.sh`), and a systemd unit template (`bookmatch.service.template`). The index builder reads `goodreads_interactions.csv`, `book_id_map.csv`, `goodreads_books.json.gz`, and `goodreads_book_authors.json.gz` from a raw directory, keeping interactions with `rating > 0` as the collaborative filtering signal. The nominal Goodreads domain is 1..5; the filter enforces no upper bound. It outputs `user_item.npz`, `book_lookup.sqlite`, and `meta.json` to an index directory, and is idempotent — it rewrites the index directory each run.

The dataset downloader fetches four files (interactions, book_id_map, books, book_authors) from `mcauleylab.ucsd.edu` using curl with resume support, retries, and a 2-hour timeout. The raw dataset is approximately 6.5 GB and is stored in a gitignored directory. The service also includes a SQL view `books.v_bookmatch_correctness` that asserts the pipeline produced a grounded result per account.

## Why it exists

bookmatch recreates the June-2026 Goodreads "impossible insights" recommendation engine as a MyApps app. It exists to give an owner a recommendation flow: add a Goodreads account, run analysis, get a taste profile plus recommendations, veto unwanted ones, and chat with an agent about what that person would like. Without it, that recommendation capability would be lost.

## How it is used

- **Owner surfaces:** `deploy.sh` deploys in-place — it refuses to deploy unless the current branch is `main`, the working tree is clean, and `HEAD` matches `origin/main`; it restarts the `bookmatch` systemd service using `sudo -n`, checks health by requiring both `ok` and `corpus_ready` from `/api/health`, records the deployed revision in `.deploy-last-good` on success, and attempts rollback to the recorded last known-good revision if health checks fail; rollback may fail or lack a target, and the deploy exits nonzero.
- **Agent surfaces:** `scripts/build_index.py` builds the neighbor-gap index from the raw UCSD Goodreads corpus; `scripts/download_dataset.sh` downloads the corpus; `scripts/install_hooks.sh` activates the tracked git hooks by setting `core.hooksPath` to `.githooks`.
- **Automatic consumers:** the SQL view `books.v_bookmatch_correctness` is the correctness surface; the capability manifest `capability.yaml` declares `cap.bookmatch-recommend`.
